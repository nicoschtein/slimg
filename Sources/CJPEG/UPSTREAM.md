# libjpeg-turbo source provenance

- Upstream: https://github.com/libjpeg-turbo/libjpeg-turbo
- Release: **3.2.0**
- Source archive: https://github.com/libjpeg-turbo/libjpeg-turbo/archive/refs/tags/3.2.0.tar.gz
- Archive SHA-256: `980dd81f425082aa6d7c9e47fef27554ce7a9ffc8e2f6e863b97d263c5c50858`
- Vendored files under `vendor/` are unmodified upstream files. `SHA256SUMS` lists their hashes.
- Upstream precision wrapper sources were generated by its `wrappers` CMake target.
- `config/` contains generated headers for libjpeg API v6.2, 64-bit macOS,
  no SIMD, no arithmetic coding, no tools, no TurboJPEG API, no profiling.
  These settings work for both supported macOS architectures (arm64 and x86_64).
- `shim.c` and `include/slimg_jpeg.h` are Slimg integration code, not upstream.

Configuration used to generate the headers:

```sh
cmake -S libjpeg-turbo-3.2.0 -B config \
  -DENABLE_SHARED=OFF -DWITH_SIMD=OFF -DWITH_TURBOJPEG=OFF \
  -DWITH_TOOLS=OFF -DWITH_TESTS=OFF \
  -DWITH_ARITH_ENC=OFF -DWITH_ARITH_DEC=OFF
cmake --build config --target wrappers
```

Only coefficient transcoding is exposed by Slimg. Input is limited to 8-bit
Huffman-coded DCT JPEGs, 128 MiB input, 524,288 coefficient blocks, and 256
progressive scans. Restart markers, ICC/JFIF/Adobe/EXIF markers, quantization,
sampling, and native coefficients are preserved. Unsupported/malformed input,
MPF auxiliary-image indexes, appended content, warnings, memory-limit failures,
late APP/COM markers that would be moved into the header, and candidates that
cannot shrink are retained unchanged.
