Features

Built to do exactly one thing, honestly.

No "visually lossless" hand-waving. Slimg removes only what doesn't affect a single pixel, and tells you precisely what it touched.

Truly lossless

Re-deflates PNG image data at zlib level 9 and drops only non-pixel bytes. Re-decode the output and you get byte-identical pixels — guaranteed never larger than the input.

Private by design

100% on-device. No uploads, no servers, no accounts, no telemetry. Slimg works fully offline — your photos and screenshots stay on your machine.

Native & fast

A native Swift app and CLI with built-in compression libraries. No Electron, separately installed tools, or background daemons. Universal binary for Apple Silicon and Intel.

Transparent reports

The advanced report shows exactly what was removed — EXIF, XMP, IPTC, comments, timestamps, re-deflated data — and how many bytes each item saved, per file.

Metadata, gone

Strips EXIF, XMP, IPTC, comments and timestamps that bloat files and leak location and device data. ICC color profiles are kept by default, so colors stay true.

App & CLI

Drag-and-drop in the SwiftUI app, or script it with the slimg command-line tool. Same lossless engine, dry-run mode, and per-file reports either way.

How it works

Three steps. Zero surprises.

Drop files in, and Slimg shows a per-file advanced report of exactly what it removed and how much each step saved.

  1. 1

    Drop your images

    Drag JPEG, PNG, GIF or HEIC files onto the app — single shots or whole folders. Or point the CLI at them.

  2. 2

    Slimg slims, losslessly

    It strips metadata and recompresses PNG image data losslessly. Optional deeper PNG, JPEG, and GIF optimization is off by default — pixels stay unchanged.

  3. 3

    Smaller files, identical pixels

    You get lighter files and a report of every byte saved. Originals are kept as name.bak.ext by default.

Lossless vs lossy

The honest difference from TinyPNG.

Both kinds of tool are useful — they just make different promises. Here's the distinction, straight.

Slimg — truly lossless

Pixels guaranteed unchanged

  • Re-decoded output is byte-for-byte identical to the original.
  • Removes metadata and re-packs the same pixels more efficiently.
  • Output is never larger than the input.
  • Runs entirely on your Mac — nothing is uploaded.
  • Best for archives, design source files, screenshots, and anything you can't risk degrading.

Lossy tools (TinyPNG & co.)

"Visually lossless" — pixels do change

  • Re-encode pixels and discard color detail to shrink harder.
  • Can reach smaller sizes — by altering the actual image data.
  • Quality loss accumulates if you re-process the same file.
  • Many run in the cloud, so images are uploaded to a server.
  • Best when maximum size reduction matters more than exact fidelity.

If you need the absolute smallest file and a little quality loss is fine, a lossy tool wins. If "identical pixels" is non-negotiable, that's Slimg.

Command line

For the terminal too.

The slimg CLI runs the same lossless engine. Script it across folders, wire it into a build, or just check what a file is carrying with --report.

  • --dry-runPreview savings without writing anything.
  • --backupKeep the original as name.bak.ext (off by default — the CLI optimizes in place unless you pass this).
  • --reportPrint the per-file advanced report.
  • --keep-metadataSlim without stripping metadata.
  • --strip-colorAlso drop the ICC color profile.
  • --no-recompressSkip PNG re-deflation.

FAQ

Questions, answered plainly.

Is it really lossless?

Yes — in the strict sense. Slimg preserves pixel values. Additional compression methods are off by default and change only how samples, JPEG coefficients, or GIF indices are stored. Every method keeps only smaller results; lossy quantization is excluded.

Does it upload my images anywhere?

No. Slimg is 100% on-device. There are no servers, no accounts, no telemetry, and it works fully offline. Your images never leave your Mac.

Which formats are supported?

JPEG, PNG, GIF and HEIC. Slimg strips metadata (EXIF, XMP, IPTC, comments, timestamps) across formats, and additionally re-deflates PNG image data losslessly. HEIC/HEIF support keeps compressed image data, orientation and color profiles intact.

Can a file come out bigger?

Never. If Slimg can't make a file smaller without changing pixels, it leaves it as-is. The output is guaranteed to be no larger than the input.

Does it keep my originals?

Yes. In the app, each original is preserved alongside the result as name.bak.ext by default (an existing backup is never overwritten). The slimg CLI optimizes in place by default — pass --backup when you want it to keep the name.bak.ext copy too.

What about color profiles?

ICC color profiles are kept by default so your colors render correctly. If you specifically want them gone, the CLI's --strip-color flag removes them too.

Is it free and open source?

Yes. Slimg is free and MIT-licensed. The full source is on GitHub, so you can audit exactly what it does.

Does it run on Intel Macs?

Yes. Slimg ships as a universal binary for both Apple Silicon and Intel, and requires macOS 13 or later.

How is it different from TinyPNG or ImageOptim?

TinyPNG is a lossy, cloud-based service — it changes pixels and uploads your images. Slimg is strictly lossless and entirely on-device. ImageOptim is a great local tool with both lossless and lossy modes; Slimg focuses purely on the lossless path with a transparent per-file report of exactly what it removed.
